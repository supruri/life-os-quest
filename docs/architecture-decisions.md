# Architecture decisions

## 2026-07-28 — Firebase is the application data platform

- **Decision:** Use Firebase Authentication and Cloud Firestore instead of Supabase for the app's authentication, user state, AI-plan queue, and future personalization data.
- **Reason:** Firestore can later store embeddings and perform indexed nearest-neighbor searches for retrieval and personalized coaching. Embeddings will be generated by a server-side model/service and stored separately from ordinary app state.
- **Owner:** Claude is responsible for the Firebase migration in the frontend and supporting backend queue integration.
- **Deployment dependency:** Do not deploy the current UI build to production until the Supabase client and `VITE_SUPABASE_*` configuration have been removed or replaced by Firebase configuration. A Supabase `service_role` key must never be bundled into a browser build.
- **Current UI work:** The responsive Figma-aligned UI changes are integrated on `b2-react-overlay` but are not deployed. Production deployment follows the Firebase migration and Firebase smoke test.

## Runtime boundaries

- Cloudflare Pages serves the web UI at `life.codemeant.dev`.
- Firestore is the source of truth for app data and future vector-search metadata.
- Local/remote LLM inference remains a separate service; Cloudflare Pages does not host Ollama or the Qwen model runtime.
